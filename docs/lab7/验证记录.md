### ArgumentCaptor 的使用（Lab 7 Step 1 明确要求）

```java
ArgumentCaptor<List<DomainEvent>> captor = ArgumentCaptor.forClass(List.class);
verify(eventPublisher).publish(captor.capture());
VoteCast event = (VoteCast) captor.getValue().get(0);
assertEquals(10, event.reputationDelta());
assertEquals(ASKER, event.targetAuthorId());
```

不只断言"publish 被调用"，而是断言**事件内容**（声誉增量 +10 / −12 / −10、目标作者）。

### 清理掉的"无效断言"

- 删除了 `assertNotNull(new Object())` 这类恒真断言；
- 把 `assertNotNull(user)` 改成 `assertEquals(UserStatus.ACTIVE, user.status())`；
- 所有时间相关测试改用 `Clock.fixed`，不再依赖机器时间。

## 6. 质量门禁与 CI

| 组件 | 配置位置 | 作用 |
|---|---|---|
| JaCoCo | 父 `pom.xml`（prepare-agent + report） | 每个模块生成 `target/site/jacoco/` |
| 覆盖率聚合 | `co-coverage/pom.xml`（`report-aggregate`） | 合并所有 exec，生成整体 `jacoco.xml` + HTML |
| 覆盖率门禁 | `tools/coverage-gate.mjs` | 整体 ≥70%、`domain/model` ≥90%，不达标退出码 1 |
| Checkstyle | 父 POM + `config/checkstyle/checkstyle.xml` | 0 violation 才继续 |
| SonarQube | `sonar-project.properties` + `docker-compose.sonarqube.yml` | 可选，需自备服务与 token |
| CI | `.github/workflows/ci.yml` | 后端 verify（含 Testcontainers）+ 前端 lint/typecheck/build；有 `SONAR_TOKEN` 时推送并 `qualitygate.wait=true` |

> **SonarQube 服务本体**：本机没有 Docker，未能在提交环境启动 SonarQube，
> 因此 Dashboard 截图需在**有 SonarQube 的环境**（老师给的服务器 / 队员装了 Docker 的机器）按
> `docker-compose.sonarqube.yml` 启动后补一张。CI 与配置已经就绪，不影响"门禁配置与持续生效"。
