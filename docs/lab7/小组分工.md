## 0. 分工原则

1. **测试按模块归属分**：谁写的业务代码，谁补自己的测试；跨模块链路由两人结对。
2. **门禁配置交给"质量值守"**：陈玉豪负责 JaCoCo/Checkstyle/CI，避免人人改 POM 互相冲突。
3. **评审交叉进行**：每人评审一个自己没参与的 PR，意见必须落到具体文件与行。
4. **数字说话**：所有"完成"都要附命令输出（覆盖率、测试数、门禁结论）。

## 3. 依赖顺序

```
WP1 基线 ──► WP2/WP3/WP4/WP5 补测试 ──► WP6 聚合与门禁 ──► WP9 契约测试 ──► 验收
                                    └──► WP7 Checkstyle/CI ──► WP8 Testcontainers（CI 上验证）
WP10 评审：可与编码并行，但必须在合并前完成
```

关键路径：**WP1 → 补测试 → WP6 门禁**。门禁阈值不要在测试补完前定死，否则会为了过门禁写无效测试。
