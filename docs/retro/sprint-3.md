## 4. 投票结果：Sprint 4 的 3 项改进行动

> 规则：每人 2 票，同一项最多 1 票；取票数最高的 3 项，且必须能写出"完成标准"。

### 行动 1：迁移脚本双环境验证（5/5 票，全票通过）

- **做什么**：任何 `V*__*.sql` 合并前，必须证明两件事：
  1. 在**空库**上 `flyway migrate` 成功；
  2. 在**当前开发库**（已有数据）上 `migrate` 成功，且历史数据回填正确。
- **完成标准**：PR 描述里贴两条 `flyway_schema_history` 查询结果；缺一条不合并。
- **负责人**：陈玉豪（SM，质量）｜**验证**：刘铭洋

### 行动 2：跨上下文事件先定契约再写代码（4/5 票）

- **做什么**：涉及两个上下文的改动（如问答 → 声誉），先在 PR 描述里列事件字段表，
  另一方确认后再写实现；字段缺失视为设计缺陷，不算"实现 bug"。
- **完成标准**：Sprint 4 的每个跨上下文 PR 都有"事件字段表"小节。
- **负责人**：陶浩峰（Dev，事件源）｜**验证**：程靖轩

### 行动 3：命令优先于判断（3/5 票）

- **做什么**：说"能跑"之前必须贴命令与输出：`mvn -q test`、`pnpm typecheck`、
  `curl` 的实际响应；口头结论不算数。
- **完成标准**：站会上"做完了"必须附一条命令输出或截图。
- **负责人**：倪昊宇（PO，验收）｜**验证**：全员
