## 0. 分工原则

1. **按"可独立验证的产物"分**：一个聚合 / 一条链路 / 一份文档，能单独 review、单独演示；
2. **作者不自评**：每个 PR 必须由另一人 review + LGTM；
3. **跨上下文改动先定事件契约**（这是 Sprint 3 回顾会选出的行动 2）；
4. **每人有备份**，任何一人缺勤，备份能接着讲、接着改。

## 3. 依赖顺序

```
WP7 迁移 ──► WP1 投票 ──┐
             WP2 回答 ──┼──► WP5 声誉（消费事件）
             WP3 评论 ──┤
             WP4 标签 ──┘
                     └──► WP6 前端 ──► WP8 E2E ──► WP9 文档
```

关键路径：**WP7 → WP1 → WP5 → WP6 → WP8**。
事件字段（`targetAuthorId`、`reputationDelta`、`previousAnswerAuthorId`）必须在 WP1/WP2 与 WP5 之间先对齐——这是本次返工的主要来源。

## 5. 两学时现场节奏（120 分钟，按 Lab 6 Step 1–3）

| 时间 | 内容 | 主讲 | 产出 |
|---|---|---|---|
| 0–5′ | 站会：昨日完成 / 今日计划 / 障碍 | 陈玉豪 | 站会纪要 |
| 5–65′ | **编码冲刺**：按 Sprint Backlog 收口，每完成一个 Task 提 PR | 全员 | 4–8 个 PR |

> Demo 顺序刻意按"用户旅程"排：先提问，再回答与采纳，然后投票与评论，最后看标签筛选与声誉数字变化。
