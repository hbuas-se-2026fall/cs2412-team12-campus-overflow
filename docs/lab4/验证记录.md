## 4. 错误分支（统一错误响应）

| 场景 | HTTP | code | 响应体（message 节选） |
|---|---|---|---|
| 标题只有 1 个字 | 400 | `VALIDATION_FAILED` | `标题长度必须在 5–150 字之间`，`details[0].field=title` |
| 标签不在 SK-01 词表 | 400 | `INV-Q-02` | `标签「我自己造的词」不在共享词表 SK-01 中，请先申请新增词条` |
| 未验证账号发帖 | 400 | `INV-U-02` | `账号当前状态为 pending，请先完成邮箱验证再发布内容` |
| 重复邮箱注册 | 409 | `INV-U-01` | `该邮箱已注册：tao@hbuas.edu.cn` |

## 7. 验证过程中发现并修掉的两个真实问题（留痕）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `mvn` 报 `需要 class、interface、enum 或 record`，定位到 `UserController.java:1` | 第四层包名用了 `com.campusoverflow.identity.interface.rest`，而 `interface` 是 Java 保留字，编译器在 `package ...interface...` 处直接语法错误 | 包名改为 `interfaces`，并写进 ADR-002 §3 的"撞坑记录" |
| 2 | 接口返回 201 且数据入库，但 JSON 日志里始终没有 `domain event published` | 应用服务从 `save()` 返回的**重建对象**上 `pullDomainEvents()`，而事件挂在**刚计算的聚合**上，导致事件永远为空 | 改为 `eventPublisher.publish(question.pullDomainEvents())`（原聚合），并补了"事件不能从重建对象取"的注释 |

第 2 个问题是这次验证最大的收获：**单元测试全绿也可能事件一条都没发出去**，因为聚合测试只断言
`pullDomainEvents()` 有值，并没有跨过应用服务。这也解释了为什么必须做一次真库 + 真日志的端到端验证。

## 8. 复现方式

```bash
# 1) 建库（表由 Flyway 建，不需要手工执行 DDL）
mysql -uroot -p -e "DROP DATABASE IF EXISTS campus_overflow; CREATE DATABASE campus_overflow DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;"

# 2) 构建
mvn clean install

# 3) 启动
java -jar co-bootstrap/target/campus-overflow.jar --server.port=18080

# 4) 用 Postman 打开 docs/api/CampusOverflow-Lab4.postman_collection.json，
#    把 baseUrl 改成 http://127.0.0.1:18080 后按 01 → 02 顺序执行。
```
