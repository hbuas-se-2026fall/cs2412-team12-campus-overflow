## 0. 分工原则（先说清楚为什么这么分）

1. **按"可独立验证的产物"分，不按技术层分**。一个人负责一个能单独 review、单独演示的部件（一个模块 / 一个提交物 / 一段流程），
   而不是"你写 Controller、我写 Service"——后者会让每个人都只看到自己那一层，出问题互相等。
2. **作者不自评**。每份 PR 必须由另一名成员 review + LGTM，SM 才能合并（Lab 1 团队章程的约定）。
3. **每人都有 1 名备份**。任何一人缺勤，备份能接着讲、接着改，避免 bus factor = 1。
4. **PO 不写最多代码，但要能解释每个决策**。ADR-002 是 PO 的产物，评审时由 PO 回答"为什么不按技术分层切模块"。
