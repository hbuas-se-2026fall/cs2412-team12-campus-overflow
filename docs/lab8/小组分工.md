## 0. 分工原则

1. **按"可独立验证的产物"切**：镜像、编排、流水线、监控、文档各归一人，避免多人同时改 compose。
2. **部署权收口**：只有陈玉豪持有服务器 SSH 与 GHCR 发布权限，减少误操作。
3. **配置即代码**：所有 compose / Prometheus / Grafana 配置都进仓库，不在服务器上手改。
4. **未验证的要标注**：本机没有 Docker，谁写的配置谁负责在 CI 或服务器上补验证并回填记录。

## 8. 风险与应对

| 风险 | 影响 | 应对 | 负责人 |
|---|---|---|---|
| 本机无 Docker，配置未跑过 | 上线时才发现问题 | CI 的 `images` Job 真实构建；服务器首次 `docker compose config` 校验 | 陈玉豪 |
| 镜像体积过大 | 部署慢、评分低 | 多阶段 + JRE alpine + `.dockerignore`；CI 缓存 | 陶浩峰 |
| 容器内以 root 运行 | 安全扣分 | 后端 `USER app`；数据库/监控不暴露公网 | 陶浩峰 |
| Nginx 反代丢 `/api` 前缀 | 全站 404 | `proxy_pass` 末尾不带 `/`，本地先验证 | 刘铭洋 |
| 指标名与看板不一致 | 看板空白 | 同一 PR 内对齐；用 `/actuator/prometheus` 实际输出命名 | 程靖轩 |
| 部署脚本误删数据 | 事故 | `up -d --no-deps app nginx`，从不 `down -v`；备份后再发布 | 陈玉豪 |
| 没有服务器/子域名 | 无法完成"上线" | 提前向课程申请；本地用 compose 演示，文档写清步骤 | 倪昊宇 |
