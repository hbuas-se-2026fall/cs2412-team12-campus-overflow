## 2. 健康检查（真实响应）

```text
GET /actuator/health            -> {"status":"UP","groups":["liveness","readiness"]}
GET /actuator/health/liveness   -> {"status":"UP"}
GET /actuator/health/readiness  -> {"status":"UP"}
```

`readiness` 组包含 `db`、`diskSpace`、`ping`，因此"容器活着但数据库断了"会被部署 smoke test 拦住。
Dockerfile 的 `HEALTHCHECK` 与 `docker-compose.yml` 的 `healthcheck` 都指向 `/actuator/health/readiness`。

## 3. Prometheus 指标（真实抓取）

先启动 jar，再通过接口造一轮真实业务：注册 2 个用户 → 提问 → 回答 → 采纳 → 投票 → 评论。

```text
$ curl -s localhost:8080/actuator/prometheus | grep '^campusoverflow_'
campusoverflow_questions_posted_total{application="campus-overflow",env="local"} 1.0
campusoverflow_answers_submitted_total{application="campus-overflow",env="local"} 1.0
campusoverflow_answers_accepted_total{application="campus-overflow",env="local"} 1.0
campusoverflow_votes_cast_total{application="campus-overflow",env="local",value="up"} 1.0
campusoverflow_comments_posted_total{application="campus-overflow",env="local"} 1.0
```

自动采集到的标准指标（节选）：

```text
hikaricp_connections_active{pool="campus-overflow-pool"} 0.0
http_server_requests_seconds_count{method="POST",status="200",uri="/api/v1/comments"} 1
http_server_requests_seconds_count{method="POST",status="200",uri="/api/v1/questions/{id}/acceptance"} 1
http_server_requests_seconds_count{method="GET",status="200",uri="/actuator/health"} 2
```

对比 Lab 8 要求"至少 5 个核心指标可观测"，我们实际可观测：

| # | 指标 | Prometheus 名 | 类型 |
|---|---|---|---|
| 1 | 提问量 | `campusoverflow_questions_posted_total` | Counter |
| 2 | 回答量 | `campusoverflow_answers_submitted_total` | Counter |
| 3 | 采纳量 | `campusoverflow_answers_accepted_total` | Counter |
| 4 | 投票量（按 up/down） | `campusoverflow_votes_cast_total{value}` | Counter |
| 5 | 评论量 | `campusoverflow_comments_posted_total` | Counter |
| 6 | 请求量 / QPS | `http_server_requests_seconds_count` | Counter |
| 7 | 延迟分布（p50/p95） | `http_server_requests_seconds_bucket` | Histogram |
| 8 | 5xx 错误率 | `http_server_requests_seconds_count{status=~"5.."}` | Counter（派生） |
| 9 | JVM 堆使用 | `jvm_memory_used_bytes{area="heap"}` | Gauge |
| 10 | 数据库连接池 | `hikaricp_connections_active/idle/pending` | Gauge |

Testcontainers 版本保留给"Docker 检测正常的本地环境"。

## 6. 仍未验证的项与原因

| 项 | 原因 | 谁/在哪验证 |
|---|---|---|
| `docker compose up` 六容器编排 | 本机无 Docker；CI 只构建镜像，不起整套 | 服务器首次部署 |
| `condition: service_healthy` 运行时行为 | 同上 | 服务器 `docker compose config` + `up -d` |
| 域名访问 / TLS | 课程子域名与服务器凭据未下发 | 按 `部署方案.md` §6 操作 |
| Grafana 看板截图 | 依赖运行中的 Grafana | 部署后打开看板截图 |
| 告警触发 | 需要真实流量打到阈值 | 可用 `hey`/`ab` 压测触发 p95 告警 |

**这不是"没做"**：Dockerfile、compose、Prometheus 规则、Grafana 看板、CI/CD 全部已提交且 CI 已验证构建；
受限的是"部署环境"（服务器 + 子域名），不是"实现"。
