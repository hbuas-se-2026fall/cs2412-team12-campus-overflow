## 7. 最容易说错的 5 组词（团队当场统一的口径）

| 易混淆 | 我们的结论 | 依据 |
|---|---|---|
| 问题 / 帖子 | 一律叫**问题**（`Question`）。"帖子"是论坛思维，会让人以为可以没有"待解决"语义 | 问答的核心是"解决"，论坛的核心是"发布" |
| 回答 / 回复 / 评论 | **回答**=`Answer` 是解决方案；**评论**=`Comment` 是补充说明。两者不是同一个东西 | 回答可被采纳，评论不能 |
| 采纳 / 点赞 | **采纳**是提问者的单次裁决（唯一）；**投票**是社区的多票评价（可叠加） | 语义与权限完全不同 |
| 声誉 / 积分 | 统一叫**声誉**（`Reputation`）。"积分"暗示可消费、可兑换，我们不做 | 声誉只增不减到 1 为止，不可消费 |
| 下架 / 删除 | **下架**=`Removal`（管理员，留痕，内容仍在）；**删除**=`Delete`（作者本人，不可逆） | 治理动作必须可追溯 |
| 模块 / 上下文 | 代码里叫**模块**（Maven module），模型边界叫**上下文**（Bounded Context） | 防止把技术分层当成业务边界 |

## 8. 命名规约（写代码前先对齐）

| 对象 | 规则 | 正例 | 反例 |
|---|---|---|---|
| 聚合 / 实体 | 单数名词，大驼峰 | `Question`、`Answer` | `Questions`、`QuestionDO` |
| 命令 | 动词+名词，祈使句 | `AcceptAnswer`、`PostQuestion` | `AnswerService.accept()` |
| 领域事件 | 名词+过去式 | `AnswerAccepted`、`VoteCast` | `OnAccept`、`acceptEvent` |
| 不变式常量 | `INV-<聚合首字母>-<序号>` | `INV-Q-04` | `CHECK_1` |
| 接口路径 | 资源复数，kebab-case | `/api/v1/questions` | `/api/getQuestion` |
| 数据库表 | 单数 snake_case | `question`、`reputation_entry` | `t_question`、`Questions` |
